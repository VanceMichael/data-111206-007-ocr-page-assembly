# 扫描申报资料的词框采集与复核流水线

读取 ALTO 词框及置信度，检查页面边界并保存原始页面；在词框之上完成页面归属、货物行组装与人工复核。

## 运行

在 Python 3.11 或更新版本的 Linux 环境使用。原始内容保存在 `output/raw.sqlite3`，流程状态保存在 `output/pipeline.sqlite3`，删除 `output/` 可回到干净状态。全部示例使用本地合成数据，不包含账号凭据或真实企业资料。

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q .
python3 app.py demo
python3 app.py pipeline
```

`app.py demo` 只列出原词框；`app.py pipeline` 演示完整流程：按扫描顺序接收乱序页（含重复扫描与二维码冲突页）、构建文档、记录复核决定、接收重识别页，最后输出哪些文档可发布、哪些还欠证据。正常执行不到 30 秒。`--output` 指定原文库，`--db` 指定流程库。

## 采集流程（pipeline.py）

可调用路径：`ingest_page`（页接收）→ `build`（构建文档状态）→ `review_queue`（待决复核项）→ `decide`（记录决定）→ `document` / `publication`（结构化结果与多久可发布）。

- **页接收**：原字节按 SHA-256 进原文库，不覆盖；词框按批次旋转角归一化到端正坐标系。词框内容指纹一致的页登记为重复扫描（只增观察，不增明细）；同一来源内容变化、同一逻辑页同一识别版本内容冲突都会被拒绝。
- **页内重建**：用框坐标把词框聚成行，从本页检测到的表头行（货物名称/数量/金额）推出列区域，不按固定 y 坐标切所有表格；表头以上的页眉数字不会成为数量。
- **页面归属**：二维码只作候选。单码页直接归属；无码页用页眉主体证据（申报企业/续页）链接到已建立主体关系的文档；多码页隔离并暂停相关文档；证据不足的页搁置，不凭文件名补齐。
- **跨页续行**：页序由页类证据决定（首页在前、续页在后），页尾缺数量的行与下一页首行合并，证据跨页记录；行未闭合或续页顺序证据不足时文档暂停。
- **人工复核**：低置信或候选冲突的关键值生成复核项，复核人看到证据与候选（OCR 原文、形近字猜测、归属候选），不是无来源的拼接字符串。决定绑定具体词框（逻辑页、识别版本、词框 ID、原文）；更换识别结果后旧决定标记未生效，不默默套到新词框，仅相关行重建。原始 OCR 各版本都可回读。

## 模块与数据

fixtures/pages 保存合成词框，fixtures/batches.json 描述扫描页、方向和二维码。

`raw_store.py` 将原始字节按 SHA-256 保存，用来源和字节摘要区分观察。它只保存原文，不表达业务结果是否完整。同一内容重复观察保留一份对象并更新观察时间，SQLite 事务保证对象和观察同时提交。所有解析异常保持非零退出码，输入原件不改写。

## 环境

`requirements.txt` 登记精确依赖。环境准备阶段安装依赖，运行、构建及测试不执行下载。正式运行可以使用依赖准备后记录的镜像 ID；镜像和验证回执保存在项目外，不影响原始内容。
